# NAI 생성 승인 원장

`tools/thumb_bench.py` 는 실행별 상한(`--max-requests`, 하드 상한 3000)만 강제하고
누적 사용량을 저장하지 않는다. 그래서 승인 상태를 여기에 기록한다.
**예약 실행은 이전 대화 기억이 없으므로 이 파일이 유일한 근거다.**

## 원 승인 (2026-07-25, 사용자 직접 발언)

> "이 작업에서 NAI API 호출을 통한 이미지 생성을 명시적으로 승인합니다.
> 승인 한도: 3000회 요청 / steps 제한 28 / image size 제한 1024 x 1024 고정 /
> 세부 파라미터는 기존 생성 이미지 메타데이터를 확인합니다."

도구가 코드로 강제하는 상한 (`tools/thumb_bench.py`):
- `HARD_MAX_REQUESTS = 3000`
- `HARD_MAX_STEPS = 28`
- `HARD_SIZE = 1024`

## 사용 이력

| 구간 | 용도 | 요청 수 |
|---|---|---|
| 2026-07-25 | 특징 슬롯 22축 (파일럿·재생성 포함) | 약 1,050 |
| 2026-07-26 | 의상 파일럿 6그룹 × 3장 (전 그룹 PASS) | 18 |
| 2026-07-26 | 의상 본 배치 + 델타(freq 500) + 액세서리 재분할 + 이관 47 | 약 1,780 |
| 2026-07-26 | 의상 본 배치 22축 (실패 0 / 재시도 0) | 864 |
| 2026-07-26 | 미렌더 시드 재생성 30 + 장신구 프레이밍 파일럿 3 | 33 |

**2026-07-26 구간 합계 915회 사용 / 3,000회 예산 → 잔여 2,085회.**
(`cloth_nsfw` 51 · `body_nsfw` 40 은 계획대로 생성하지 않음)

## 한도 초기화 (2026-07-26 06:00 KST)

> "KST 오전 6시가 되면 기존에 설정되어있던 한도를 초기화하고,
> 의상 섹션을 생성할 수 있도록 1회성 Loop 설정을 해주십시오."

- 사용자가 2026-07-26 06:00 KST 부터 **한도를 초기화**했다.
- 초기화 후 예산: **3,000회** (steps 28 / 1024px 고정은 그대로 유지).
- 용도: **의상 섹션**.

`cloth_nsfw` 51장은 **생성하지 않는다** — `body_nsfw` 40장과 같이 사용자가 직접 한다.

## 지켜야 할 것

- 이 원장에 적힌 것 외의 용도로 생성하지 않는다.
- 성인 축(`body_nsfw`, `cloth_nsfw`)은 생성하지 않는다.
- 파일럿을 먼저 돌리고 Vision 으로 확인한 뒤 본 배치를 돌린다.
  특징 슬롯에서 파일럿 27장이 축 단위 프레이밍 실패 3건을 잡아 수백 장을 절약했다.


## 2차 한도 초기화 (2026-07-26, 자세 섹션)

> "한도 3천 -> 0으로 초기화 후 한도를 3500으로 늘리고 자세 시작합니다."

- 누적 사용량을 **0 으로 초기화**했다. 의상 섹션까지의 사용분은 위 이력에 남긴다.
- 초기화 후 예산: **3,500회** (`HARD_MAX_REQUESTS` 도 3000 -> 3500 으로 올렸다).
- steps 28 / 1024px 고정은 그대로다.
- 용도: **자세 섹션**.

자세 대상은 개별 슬롯 1,600 + 글로벌 440 = 2,040장이다(성인 122·제외 87 제외).
파일럿을 먼저 돌리고 프레이밍을 확인한 뒤 본 배치를 돌린다.

### 자세 섹션 실사용 (2026-07-26 갱신)

| 구분 | 장수 | 비고 |
|---|---|---|
| 1차 본 배치 (12:00~17:06) | 약 1,620 | 실패 0 / Rate Limit 0 |
| 다인원 파일럿 2회 | 12 | 8 + 4 (프레이밍 재확인) |
| 2차 본 배치 (17:20~) | 869 | 다인원 재생성 384 + 재분할 누락분 |
| **누계 예상** | **약 2,500** | 예산 3,500 |

2차가 생긴 이유 두 가지를 남긴다. 둘 다 **조용히 틀리는** 종류였다.

1. **다인원 축이 `1girl, solo` 로 찍혔다.** 자세를 개별/글로벌로 가른 이유 자체를
   템플릿이 뒤집고 있었다. `hug` 은 인형을 안은 1인, `piggyback` 은 혼자 허리를
   숙인 그림이 나왔다. 384장을 치우고 `2girls` 로 다시 찍는다. 인원 구성은 실측상
   girl+boy 41~57% / 2girls 29~47% 로 우열이 없어 화면 톤을 기준으로 골랐다.
   파일럿에서 portrait 크롭에는 두 사람이 안 들어간다는 것도 잡혔다(다인원 얼굴
   축은 upper 로 올림).
2. **`_todo/` 가 축 파일과 갈라져 있었다.** thumb_bench 는 `_todo/<axis>.txt` 를
   읽는데 build_pose_axes 는 `<axis>.txt` 만 썼다. 재분할 뒤 벤치가 옛 목록을
   찍고 있었고, 신설 축 `pose_leg`(71장)은 `_todo` 파일이 없어 경고 한 줄만 남기고
   통째로 건너뛰었다 — 결과물을 세어보기 전엔 드러나지 않는다.
   build_pose_axes 가 `_todo` 도 같이 쓰도록 고쳤다.
